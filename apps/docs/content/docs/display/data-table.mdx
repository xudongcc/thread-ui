## API Style

`DataTable` uses a [props-first API](/docs/api-design/props-first). Pass row data,
column definitions, actions, and pagination behavior as configuration props.

## Installation

```bash
pnpm dlx shadcn@latest add @thread-ui/data-table
```

## Usage

```tsx
import {
  DataTable,
  type DataTableColumnProps,
} from "@/components/thread-ui/data-table";
```

```tsx
interface User {
  id: string;
  name: string;
  email: string;
}

const columns: Array<DataTableColumnProps<User>> = [
  {
    id: "name",
    header: "Name",
    accessorKey: "name",
  },
  {
    id: "email",
    header: "Email",
    accessorKey: "email",
  },
];

const data: Array<User> = [
  { id: "1", name: "Alice", email: "alice@example.com" },
  { id: "2", name: "Bob", email: "bob@example.com" },
];

<DataTable columns={columns} data={data} />;
```

## Localization

`DataTable` reads its built-in empty state, selection controls, row action trigger labels, and pagination labels from `AppProvider`. Register the `thread-ui` namespace on your i18next instance and pass that instance to `AppProvider`.

## Features

- **Row Selection** - Single and multi-row selection with bulk actions support
- **Row Actions** - Dropdown menu with customizable actions per row
- **Column Pinning** - Pin columns to the left or right for better visibility
- **Pagination** - Built-in pagination controls
- **Row Click** - Handle row click events for navigation or detail views
- **Flexible Columns** - Thread UI column definitions with custom headers, cells, and accessors

### Custom cell and row contexts

`cell` receives `{ row, column, getValue }`; `header` receives `{ column }`.
`row`, including the row passed to `rowActions`, action callbacks, and `onRowClick`,
contains only `{ id, index, original }`. `onRowSelectionChange` receives the original
records. No TanStack instance or methods are exposed.

```tsx
const columns: DataTableColumnProps<User, string>[] = [
  {
    id: "contact",
    accessorFn: (user) => `${user.name} <${user.email}>`,
    header: "Contact",
    cell: ({ getValue }) => <strong>{getValue()}</strong>,
  },
];
```

`accessorKey` supports dotted object paths. If it is omitted, `id` is used as the
accessor unless `accessorFn` is provided. Supply an explicit `id` for computed
columns. Column sizing and left/right pinning are supported; sorting, filtering,
and pagination of the input records remain the application's responsibility.

When migrating from the old inherited types, replace engine-specific calls such
as `row.getValue("name")` with `row.original.name`, or use `getValue()` inside a
cell. Custom headers no longer receive a table instance.
