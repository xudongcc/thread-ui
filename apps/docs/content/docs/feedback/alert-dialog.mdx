## API Style

AlertDialog supports both a [function-based API](/docs/api-design/function-based)
and JSX composition from `@/components/thread-ui/alert-dialog`.
Mount `AlertDialogProvider` once (or use `AppProvider`), then call `alertDialog()`
and await its boolean result from event handlers or async workflows.
For custom JSX layouts and local state, compose `AlertDialog` and its child
components directly; this mode does not require a provider.

## Installation

```bash
pnpm dlx shadcn@latest add @thread-ui/alert-dialog
```

## Setup

For function calls, add `AlertDialogProvider` to your root layout. Skip this step
if you already use `AppProvider`, which includes it, or only use JSX composition:

```tsx
import { AlertDialogProvider } from "@/components/thread-ui/alert-dialog";

export default function RootLayout({ children }) {
  return (
    <html lang="en">
      <body>
        <AlertDialogProvider>{children}</AlertDialogProvider>
      </body>
    </html>
  );
}
```

## Usage

### Function API

```tsx
import { alertDialog } from "@/components/thread-ui/alert-dialog";
```

```tsx
const handleDelete = async () => {
  const confirmed = await alertDialog({
    title: "Delete item?",
    description: "This action cannot be undone.",
    confirmText: "Delete",
    variant: "destructive",
  });

  if (confirmed) {
    // Perform delete action
  }
};
```

## Examples

### Composition API

Import `AlertDialog`, `AlertDialogTrigger`, `AlertDialogContent`,
`AlertDialogHeader`, `AlertDialogTitle`, `AlertDialogDescription`,
`AlertDialogFooter`, `AlertDialogCancel`, and `AlertDialogAction` from the same
Thread UI entry point as `alertDialog()`.

<Preview path="alert-dialog-composition" />

`AlertDialogCancel` closes the dialog automatically. `AlertDialogAction` is a
button: handle the action yourself and set `open` to `false` when it succeeds.
For async operations, keep it open until the operation finishes and disable the
button while pending. Composition does not return a `Promise<boolean>`; use your
own callbacks and state.

`AlertDialogMedia`, `AlertDialogOverlay`, and `AlertDialogPortal` are also exported
for custom layouts. `AlertDialogContent` already includes its portal and overlay.

## Features

- **Function-based API**: Call `alertDialog()` anywhere without hooks
- **Composition API**: Build JSX layouts and control open state without a provider
- **Promise-based**: Returns a Promise that resolves to `true` or `false`
- **Icon Support**: Add icons for visual context
- **Size Variants**: Choose between default and small sizes
- **Customizable**: Configure title, description, button text, and variant
- **Accessible**: Built on Base UI AlertDialog with proper ARIA attributes
- **Async/Await Support**: Easily integrate with async workflows

## Best Practices

- Use for irreversible or important actions that need user confirmation
- Provide clear, concise titles that describe the action
- Use descriptions to explain the consequences of the action
- Use `variant: "destructive"` for delete or dangerous operations
- Keep button text short and action-oriented

## API Reference

### AlertDialogProvider

The provider component that enables alert dialogs throughout your app.

### alertDialog(options)

Shows an alert dialog and returns a Promise.

```tsx
import { Trash2Icon } from "lucide-react";

const confirmed = await alertDialog({
  title: "Delete item?",
  description: "This action cannot be undone.",
  icon: <Trash2Icon />,
  size: "default",
  cancelText: "Cancel",
  confirmText: "Delete",
  variant: "destructive",
});
```
