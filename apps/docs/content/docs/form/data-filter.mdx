## API Style

`DataFilter` uses a [props-first API](/docs/api-design/props-first). Filters,
search, and sorting are configured as data; render callbacks provide an escape
hatch for custom fields and values.

## Installation

```bash
pnpm dlx shadcn@latest add @thread-ui/data-filter
```

## Usage

```tsx
import {
  DataFilter,
  type DataFilterField,
  type DataFilterValue,
} from "@/components/thread-ui/data-filter";
```

```tsx
const filters: DataFilterField[] = [
  {
    field: "name",
    label: "Name",
    type: "input",
    defaultOperator: "$fulltext",
    operators: ["$eq", "$ne", "$fulltext"],
    placeholder: "Filter by name...",
  },
  {
    field: "amount",
    label: "Amount",
    type: "number-input",
    defaultOperator: "$gte",
    operators: ["$eq", "$ne", "$gt", "$gte", "$lt", "$lte", "$between"],
    min: 0,
    max: 10000,
    decimalScale: 2,
  },
  {
    field: "age",
    label: "Age",
    type: "number-input",
    defaultOperator: "$between",
    operators: ["$eq", "$ne", "$gt", "$gte", "$lt", "$lte", "$between"],
    min: 0,
    max: 120,
  },
  {
    field: "createdAt",
    label: "Created At",
    type: "date-picker",
    defaultOperator: "$between",
    operators: ["$eq", "$ne", "$gt", "$gte", "$lt", "$lte", "$between"],
    min: new Date("2024-01-01"),
    max: new Date("2026-12-31"),
  },
  {
    field: "archived",
    label: "Archived",
    type: "checkbox",
    defaultOperator: "$eq",
    operators: ["$eq", "$ne"],
  },
];

const value: DataFilterValue = {
  query: "Acme",
  orderBy: {
    field: "createdAt",
    direction: "DESC",
  },
  filter: {
    amount: {
      $gte: 100,
    },
    age: {
      $between: [18, 30],
    },
    createdAt: {
      $between: ["2025-03-01T00:00:00.000Z", "2025-03-15T00:00:00.000Z"],
    },
    name: {
      $fulltext: "Acme",
    },
    archived: {
      $eq: true,
    },
  },
};

<DataFilter filters={filters} value={value} onChange={(v) => console.log(v)} />;
```

## Localization

`DataFilter` reads its built-in labels from `AppProvider`. Register the `thread-ui` namespace on your i18next instance and pass that instance to `AppProvider`.

```tsx
import { createInstance } from "i18next";
import HttpBackend from "i18next-http-backend";
import { initReactI18next } from "react-i18next";
import { AppProvider } from "@/components/thread-ui/app-provider";
import { DataFilter } from "@/components/thread-ui/data-filter";

const i18n = createInstance();

void i18n
  .use(HttpBackend)
  .use(initReactI18next)
  .init({
    fallbackLng: "en",
    backend: {
      loadPath: "/locales/{{lng}}/{{ns}}.json",
    },
    interpolation: {
      escapeValue: false,
    },
    lng: "zh",
    ns: ["thread-ui"],
  });

<AppProvider i18n={i18n}>
  <DataFilter filters={filters} />
</AppProvider>;
```

The built-in date picker uses the shared `Calendar`, which reads calendar labels from the `thread-ui` i18next namespace. Override component copy by merging resources into that namespace.

```tsx
void i18n.addResourceBundle(
  "en",
  "thread-ui",
  {
    dataFilter: {
      addFilter: "Add condition",
      operators: {
        $fulltext: "matches",
      },
    },
  },
  true,
  true,
);
```

## Standalone filter item

`DataFilterItem` edits one controlled condition without a `DataFilter` toolbar.
Pass the configuration fields directly or spread a `DataFilterField`.
`value` is the condition object (for example `{ $eq: "Thread" }`), and `onChange`
receives the edited condition. Pass it back through `value` to accept the change.
Unlike the toolbar's submitted query, this preserves the selected operator with
an empty value and partially entered ranges (for example `{ $between: [10, undefined] }`).
Set `value` to `undefined` to reset the item. Validate or clean incomplete
conditions before using them in a query.
It shares the built-in editors, translations, and async select behavior with
`DataFilter`. Configure translations through `AppProvider` as usual.

```tsx
import { useState } from "react";
import {
  DataFilterItem,
  type DataFilterConditionValue,
} from "@/components/thread-ui/data-filter";

function NameFilter() {
  const [condition, setCondition] = useState<DataFilterConditionValue>();

  return (
    <DataFilterItem
      field="name"
      label="Name"
      type="input"
      operators={["$eq", "$ne", "$fulltext"]}
      defaultOperator="$fulltext"
      placeholder="Enter a name"
      value={condition}
      onChange={setCondition}
      onRemove={() => setCondition(undefined)}
    />
  );
}
```

The popover starts closed. `onRemove` shows a remove action; the parent decides
whether to clear the condition or remove the item entirely. Omit `onRemove` to
hide that action. Trigger, operator selector, and popover layout are internal.

For a custom editor, use the same `render` callback as `DataFilter.filters`:

```tsx
import { Input } from "@/components/ui/input";

<DataFilterItem
  field="name"
  label="Name"
  type="input"
  value={condition}
  onChange={setCondition}
  render={({ field, operator }) => (
    <Input
      aria-label="Name"
      placeholder={`Value for ${operator}`}
      value={field.value ?? ""}
      onChange={(event) => field.onChange(event.target.value || undefined)}
    />
  )}
/>;
```

`render` receives the selected `operator` and raw `field.value` / `field.onChange`.
Without `render`, the editor is selected by `type`. Empty/not-empty operators
hide the editor automatically. `DataFilter.filters` remains a configuration
array and continues to use its `render` callback.

The field configuration type is `DataFilterField`;
`DataFilterItemProps` describes the standalone component, including its controlled
value and callbacks.

### DataFilterOperator

Built-in filters support `$eq`, `$ne`, `$gt`, `$gte`, `$lt`, `$lte`, `$between`, `$fulltext`, `$in`, and `$nin`. Input filters support `$eq`, `$ne`, and `$fulltext`; number-input and date-picker filters support `$eq`, `$ne`, `$gt`, `$gte`, `$lt`, `$lte`, and `$between`; checkbox filters support `$eq` and `$ne`; select filters support `$in` and `$nin`.

The number-input and date-picker `$between` operators output a native range tuple inside `value.filter`, for example `{ age: { $between: [18, 30] } }` or `{ createdAt: { $between: ["2025-03-01T00:00:00.000Z", "2025-03-15T00:00:00.000Z"] } }`. A `$between` filter is included in `value.filter` only after both range endpoints are set.

All built-in filter types also support `is empty` and `is not empty`. These options output `$eq: null` and `$ne: null` respectively, and the value editor content is hidden while either option is selected.
