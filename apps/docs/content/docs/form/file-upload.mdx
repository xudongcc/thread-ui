## API Style

`FileUpload` supports props and composition APIs. Without `children`, it renders
an upload area and a removable [Attachment](https://ui.shadcn.com/docs/components/base/attachment)
list. Pass `children` to replace the entire default UI and compose your own layout.
Both modes support controlled and uncontrolled file selection. An optional
`onUpload` handler connects your upload workflow; the built-in p-queue manages
concurrency, task state, cancellation, and explicit retries.

## Installation

```bash
pnpm dlx shadcn@latest add @thread-ui/file-upload
```

## Usage

```tsx
import { FileUpload } from "@/components/thread-ui/file-upload";
```

```tsx
<FileUpload
  multiple
  accept="image/*,.pdf"
  title="Upload attachments"
  description="Choose files, drop them here, or paste from the clipboard."
  value={files}
  onChange={setFiles}
/>
```

Omit `value` to let the component manage its own files; use `defaultValue` for
initial files. `title` is optional and `description` falls back to the localized
`placeholder`. `className` styles the root wrapper in both modes.

The built-in Attachment list shows local image thumbnails and automatically chooses
icons for video, audio, spreadsheets, presentations, archives, and documents
(including PDF). Image preview URLs are released on removal or unmount. Recognized
MIME types take priority; filenames provide a case-insensitive extension fallback.
Unknown files use a generic file icon. No additional props are needed.

Passing `children` (including `null`) selects composition mode. In this mode,
`FileUpload` adds no default dropzone or attachment list. Use `FileUploadDropzone`
for file selection and compose Attachment components with `useFileUpload()`,
or use `FileUploadList` with `FileUploadItem`. Keep attachment
actions outside the dropzone so they do not open the file picker.

Pass custom prompt content directly to `FileUploadDropzoneDescription`:

```tsx
<FileUpload>
  <FileUploadDropzone>
    <FileUploadDropzoneDescription>
      Drop files here.
    </FileUploadDropzoneDescription>
  </FileUploadDropzone>
  <FileUploadList />
</FileUpload>
```

The description renders its `children`. In the default UI, FileUpload supplies
`description` or the localized `placeholder` explicitly.

### Staged uploads

`onUpload` runs once per file with a single context argument. Return your final
attachment object after all stages succeed. `onUploadComplete` receives all results
in selection order, including for a single-file upload.

<Preview path="file-upload-staged" />

```tsx
// These request helpers belong to your application.
<FileUpload
  multiple
  concurrency={3}
  onUpload={async ({ file, signal, setStage, onProgress }) => {
    const target = await createUploadTarget(file, { signal });
    setStage("uploading");
    await uploadToStorage(target, file, { signal, onProgress });
    setStage("processing");
    return await completeUpload(target, { signal });
  }}
  onUploadComplete={(results) => {
    saveAttachments(results.map((result) => result.url));
  }}
  onUploadError={(error, entry) => {
    console.error(entry.file.name, error);
  }}
/>
```

The handler receives `file`, `signal`, `setStage(stage)`, and `onProgress(percent)`.
Stages are `preparing` (the initial stage), `uploading`, and `processing`. Progress
is a transfer percentage from 0 to 100, not completion of the entire workflow.
Return the final resource URL or attachment ID from your confirmation endpoint,
not the presigned upload URL. Throw to report a failure.

- `concurrency` is a positive integer (default `3`). Set `1` for serial uploads.
  One queue slot covers the entire workflow, including preparation and confirmation.
- `autoUpload` defaults to `true` when `onUpload` is provided. With `false`, use
  the built-in upload action, `ref.current?.upload()`, or `useFileUpload().upload()` to start idle tasks.
- `onUploadComplete` fires only when every currently selected file succeeds.
  Files added during uploading are included. Idle, failed, and canceled entries
  block completion; an empty selection never completes. Re-renders do not repeat
  the callback. Adding files or retrying tasks can produce a new completion, whose
  results also include retained successful files.
- `onUploadError` reports a single failed task. Retrying runs the full handler with
  a new signal, allowing your application to obtain fresh credentials.
- Pass `signal` to every request and stop work when aborted. Canceling, removing,
  replacing, or unmounting aborts outstanding work; late results are ignored.
  Removing an item does not delete a remote object. In controlled mode, update
  `value` to accept the removal.
- `disabled` pauses queued tasks and disables user actions; running tasks may
  finish. Re-enabling resumes queued work. Progress updates do not call `onChange`.

### Manual upload with a ref

Use `autoUpload={false}` and a `ref` to start uploads from an external button while
keeping the default dropzone and Attachment list. No `children` or Context hook
is required. This also works in composition mode.

<Preview path="file-upload-manual" />

```tsx
import { useRef } from "react";
import {
  FileUpload,
  type FileUploadHandle,
} from "@/components/thread-ui/file-upload";

type AttachmentResult = { id: string; url: string };

function Example() {
  const uploadRef = useRef<FileUploadHandle<AttachmentResult>>(null);

  return (
    <>
      <FileUpload
        ref={uploadRef}
        multiple
        autoUpload={false}
        onUpload={uploadFile}
        onUploadComplete={(results) => saveAttachments(results)}
      />
      <button type="button" onClick={() => uploadRef.current?.upload()}>
        Start upload
      </button>
    </>
  );
}
```

Here `uploadFile` is your staged-upload handler returning `Promise<AttachmentResult>`.
The ref exposes component actions, not the hidden input DOM element. It becomes
`null` on unmount. Actions respect `disabled` and use the same queue as
`useFileUpload()`.

## Features

- **Click to Browse**: Opens the native file picker from a focused drop zone
- **Drag & Drop**: Accepts dropped files and appends them when `multiple` is enabled
- **Paste Support**: Reads file items from the clipboard when focused
- **Controlled & Uncontrolled**: Supports `value`, `defaultValue`, and `onChange`
- **Native Input Props**: Supports `accept`, `multiple`, `disabled`, `name`, and other file input props

## Best Practices

- Use `multiple` when users may provide more than one file
- Use `accept` to guide file selection, but validate files on the server too
- Pair the upload area with a `FieldLabel` and `FieldDescription` for clear form context
- Treat `value` as the source of truth in forms that need external validation

## Accessibility

File removal labels use `fileUpload.removeFile` in the `thread-ui` i18next
namespace provided through `AppProvider`, with the original filename interpolated
as `name`. The default description uses `fileUpload.placeholder`. Custom `title`
and `description` content is localized by the caller. Root `aria-label` and
`aria-labelledby` also label the interactive dropzone.

Without `onUpload`, attachments stay
in `idle`. With a handler, Attachment reflects task state and announces status
updates. Upload, cancel, and retry labels and all status messages use the
`fileUpload` locale keys; interpolated filenames remain literal text.

### FileUploadHandle

| Method             | Behavior                                                             |
| ------------------ | -------------------------------------------------------------------- |
| `upload(id?)`      | Start one idle task, or all idle tasks when omitted                  |
| `retry(id)`        | Restart a failed or canceled task                                    |
| `cancel(id)`       | Cancel an idle, queued, or running task                              |
| `remove(id)`       | Cancel and remove a file; controlled callers must update `value`     |
| `openFileDialog()` | Open the native file picker                                          |
| `getEntries()`     | Read the current tasks, including IDs, status, progress, and results |

`getEntries()` is an on-demand snapshot, not a React subscription. Use callbacks
for external UI updates, or `useFileUpload()` in descendants for reactive state.
The handle's generic type describes the result returned by `onUpload`.

### useFileUpload

Call `useFileUpload()` in any descendant of `FileUpload` to share its built-in
Context. It works with both `value` / `onChange` and `defaultValue`; the composition
example above does not need its own state.

| Member                  | Behavior                                                       |
| ----------------------- | -------------------------------------------------------------- |
| `files`                 | Current `File[]`                                               |
| `multiple` / `disabled` | Selection settings from the root                               |
| `isDragging`            | Whether files are being dragged over the dropzone              |
| `addFiles(files)`       | Append in multiple mode, otherwise replace with the first file |
| `removeFile(index)`     | Remove a file by its current index                             |
| `openFileDialog()`      | Open the native picker, even without a `FileUploadDropzone`    |

The hook also exposes upload state and actions:

| Member        | Behavior                                                                                     |
| ------------- | -------------------------------------------------------------------------------------------- |
| `entries`     | Ordered tasks with stable `id`, `file`, `status`, optional `progress`, `result`, and `error` |
| `upload(id?)` | Enqueue one idle task, or all idle tasks when omitted                                        |
| `retry(id)`   | Restart an error or canceled task                                                            |
| `cancel(id)`  | Abort one queued/running task, or cancel an idle task                                        |
| `remove(id)`  | Cancel and remove a selected file by its stable task ID                                      |

Task statuses are `idle`, `queued`, `preparing`, `uploading`, `processing`, `done`,
`error`, and `canceled`. Task IDs are incrementing strings scoped to each FileUpload
instance and remain stable through reordering and retries.
Duplicate file selections get separate task IDs. Keep the
same `File` objects in a controlled `value` to preserve task identity. The parent
may copy, filter, or reorder the array returned by `onChange`; it does not need
to retain that array reference.
Use `useFileUpload<AttachmentResult>()` to type `entry.result`; the generic must
match the enclosing FileUpload handler's return type.

Selection actions can be combined in one handler: `addFiles(files); upload()`
starts the files selected at the time of `upload()`, once the selection is accepted.
Files added after that call require another start when `autoUpload={false}`.
Removing and re-adding a file creates a new task; an earlier upload request does
not transfer to the replacement.

Actions respect `disabled`. Controlled selection actions call `onChange`; update
`value` there to accept the selection. Rejected files are never uploaded, and their
upload requests are discarded. The hook must be used inside `FileUpload`. The native input belongs
to the root, so custom picker buttons can use `openFileDialog()` directly.
