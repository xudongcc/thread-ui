## API Style

`FileUpload` supports props and composition APIs. Without `children`, it renders
an upload area and a removable [Attachment](https://ui.shadcn.com/docs/components/base/attachment)
list. Pass `children` to replace the entire default UI and compose your own layout.
Both modes support controlled and uncontrolled file selection. Upload requests,
progress, and retries are managed by your application.

## Installation

```bash
pnpm dlx shadcn@latest add @thread-ui/file-upload
```

## Usage

```tsx
import { FileUpload } from "@/components/thread-ui/file-upload";
```

```tsx
<FileUpload
  multiple
  accept="image/*,.pdf"
  title="Upload attachments"
  description="Choose files, drop them here, or paste from the clipboard."
  value={files}
  onChange={setFiles}
/>
```

Omit `value` to let the component manage its own files; use `defaultValue` for
initial files. `title` is optional and `description` falls back to the localized
`placeholder`. `className` styles the root wrapper in both modes.

Passing `children` (including `null`) selects composition mode. In this mode,
`FileUpload` adds no default dropzone or attachment list. Use `FileUploadDropzone`
for file selection and compose Attachment components with `useFileUpload()`,
or use the existing `FileUploadList` and `FileUploadPreview` helpers. Keep attachment
actions outside the dropzone so they do not open the file picker.

## Examples

### Multiple

Use the `multiple` prop to allow several files. New dropped, pasted, or selected files are appended to the current list.

<Preview path="file-upload-multiple" />

### Preview

Use `FileUploadPreview` to render Attachment cards with image and video previews in a grid. Preview object URLs are released when files change or the component unmounts.

```tsx
<FileUpload multiple accept="image/*,video/*">
  <FileUploadDropzone />
  <FileUploadPreview>
    <FileUploadPreviewItem />
  </FileUploadPreview>
</FileUpload>
```

## Features

- **Click to Browse**: Opens the native file picker from a focused drop zone
- **Drag & Drop**: Accepts dropped files and appends them when `multiple` is enabled
- **Paste Support**: Reads file items from the clipboard when focused
- **Controlled & Uncontrolled**: Supports `value`, `defaultValue`, and `onChange`
- **Native Input Props**: Supports `accept`, `multiple`, `disabled`, `name`, and other file input props

## Best Practices

- Use `multiple` when users may provide more than one file
- Use `accept` to guide file selection, but validate files on the server too
- Pair the upload area with a `FieldLabel` and `FieldDescription` for clear form context
- Treat `value` as the source of truth in forms that need external validation

## Accessibility

File removal labels use `fileUpload.removeFile` in the `thread-ui` i18next
namespace provided through `AppProvider`, with the original filename interpolated
as `name`. The default description uses `fileUpload.placeholder`. Custom `title`
and `description` content is localized by the caller. Root `aria-label` and
`aria-labelledby` also label the interactive dropzone.

The built-in list uses `ul` / `li` semantics. Selected attachments have `state="idle"`;
selecting a file does not imply that it has been uploaded.

### useFileUpload

Call `useFileUpload()` in any descendant of `FileUpload` to share its built-in
Context. It works with both `value` / `onChange` and `defaultValue`; the composition
example above does not need its own state.

| Member                  | Behavior                                                       |
| ----------------------- | -------------------------------------------------------------- |
| `files`                 | Current `File[]`                                               |
| `multiple` / `disabled` | Selection settings from the root                               |
| `isDragging`            | Whether files are being dragged over the dropzone              |
| `addFiles(files)`       | Append in multiple mode, otherwise replace with the first file |
| `removeFile(index)`     | Remove a file by its current index                             |
| `openFileDialog()`      | Open the native picker, even without a `FileUploadDropzone`    |

Actions respect `disabled`. Controlled actions call `onChange`; the caller must
update `value`. The hook must be used inside `FileUpload`. The native input belongs
to the root, so custom picker buttons can use `openFileDialog()` directly.
