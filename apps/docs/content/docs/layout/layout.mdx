---
title: Layout
description: Application shell with a top bar, shadcn sidebar, and mobile drawer navigation.
---

`Layout` provides the application frame. Use `Page` and `PageLayout` inside it
to organize page content. The top bar remains visible while the main area and
navigation scroll independently. The main area uses Base UI ScrollArea with
shadcn scrollbars. Its viewport renders as the main landmark, so
`contentProps.ref` and `contentProps.onScroll` still refer to the scrolling
element. Scrollbars appear when content overflows; nested tables can retain
their own horizontal scrolling.

## Installation

```bash
pnpm dlx shadcn@latest add @thread-ui/layout
```

## Props API

```tsx
import { Layout } from "@/components/thread-ui/layout";
import {
  TopbarMenu,
  TopbarMenuTrigger,
  TopbarMenuContent,
  TopbarMenuWorkspaceGroup,
  TopbarMenuWorkspaceItem,
} from "@/components/thread-ui/topbar";

<Layout
  brand="Acme"
  navigation={[
    {
      id: "main",
      items: [
        { id: "home", label: "Home", href: "/", active: true },
        { id: "orders", label: "Orders", href: "/orders", badge: 6 },
      ],
    },
  ]}
  search={<input type="search" aria-label="Search" />}
  topbarMenu={
    <TopbarMenu currentWorkspace={currentWorkspace}>
      <TopbarMenuTrigger />
      <TopbarMenuContent>
        <TopbarMenuWorkspaceGroup
          value={workspaceId}
          onValueChange={switchWorkspace}
        >
          {workspaces.map((workspace) => (
            <TopbarMenuWorkspaceItem key={workspace.id} workspace={workspace} />
          ))}
        </TopbarMenuWorkspaceGroup>
      </TopbarMenuContent>
    </TopbarMenu>
  }
>
  <h1>Overview</h1>
</Layout>;
```

`brand` is required. Optional `search`, `actions`, `topbarMenu`, and
`sidebarFooter` slots accept React nodes. Navigation items support icons,
badges, links, active/disabled states, and an `onClick` handler. Calling
`event.preventDefault()` also prevents automatic mobile drawer dismissal.

The header is the independent [Topbar](/docs/layout/topbar) component. Layout
provides its mobile navigation trigger and sidebar state. `topbarMenu` accepts a
`TopbarMenu` or a custom control.

The desktop sidebar is always visible, with no collapse button.
`contentProps` forwards
attributes to the main landmark. The component fills the viewport and supplies
a keyboard skip link. Mount one application Layout per page.

## Composition API

Pass `sidebar` to replace generated navigation. Compose shadcn `SidebarGroup`,
`SidebarMenu`, and `SidebarMenuButton` there, or use the exported
`LayoutNavigation` helper inside Layout. Custom router links can use shadcn's
`render` prop. Call `useSidebar().setOpenMobile(false)` after custom navigation.

## Mobile

Below 768px, the sidebar becomes a shadcn Sheet. The menu button, Escape,
outside clicks, and selecting a destination dismiss it. Focus returns to the
menu button. The mobile drawer starts directly with navigation, without a brand
header. The brand remains in the desktop top bar. Resize back to desktop to dismiss an open
drawer. The navigation toggle is only visible on mobile.

Full interactive examples live under **Storybook → Layout → Layout**; use the
viewport, theme, and language toolbars on the same examples.

## Integrated examples

Storybook includes three distinct examples: the application dashboard, an orders
page using `Page`, `DataFilter`, and `DataTable`, and a collection detail page using
`PageLayout` with two-thirds content and one-third settings. The detail columns
stack on narrow screens.

The orders example filters sample data by search, fulfillment, and amount.
Search commits on Enter or blur. Filters reset pagination and row selection;
the table supports previous/next navigation and bulk fulfillment.
