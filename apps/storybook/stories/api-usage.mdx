# API usage

Start with **Props API** whenever the component supports it. It is the first
example and the primary Autodocs preview. **Composition API** and **Function API**
examples are shown separately where supported. Existing story URLs remain stable.

Regular React props such as `open`, `className`, or `children` do not by themselves
make a component a Props API convenience component. For example, Dialog still
requires its content, title, and other parts to be composed. AlertDialog has no
single-component `title`/`description` convenience API; those options belong to
the `alertDialog()` function.

## Props API

Supply data and configuration to a single component. Controls edit those props.
For collection inputs, pass `items`; for FileUpload, omit children to use its
built-in dropzone and file list.

## Composition API

Use named child components when you need to control content or layout. Import
them from the same Thread UI entry point. CheckboxGroup and RadioGroup accept
either `items` or item children; do not provide both. FileUpload children replace
its default layout.

## Function API

Mount AppProvider once, or install the corresponding AlertDialogProvider or
ToastProvider. Then call the exported function from an event handler or workflow.
The options object configures a function call; it is not a component Props API.

```tsx
import { alertDialog } from "@/components/thread-ui/alert-dialog";
import { toast } from "@/components/thread-ui/toast";

async function handleSave() {
  const confirmed = await alertDialog({
    title: "Save changes?",
    description: "Confirm to save your current changes.",
  });
  if (!confirmed) return;

  // Save your changes here.
  toast.add({ title: "Changes saved", type: "success" });
}
```

## Application layout

The Layout stories include a dashboard, a `Page` + `DataFilter` + `DataTable`
orders page, and a two-column collection editor built with `PageLayout`.
Search, fulfillment/amount filtering, pagination, and bulk fulfillment operate
on local sample data. The collection editor supports save/discard and stacks
its columns on mobile.

`Layout` supplies the application shell; `Page` and `PageLayout` organize its
content. It supplies SidebarProvider and a responsive Grid. Compose Topbar,
the original shadcn Sidebar, and LayoutContent as children. LayoutContent
provides the independently scrolling main landmark. Missing Sidebar or Topbar
parts leave their space available to the content. Navigation uses composed
shadcn menu components and useSidebar for mobile dismissal. Layout and Topbar
support **Composition API only**. Arrange `TopbarBrand`, `TopbarSidebarTrigger`, and
`TopbarActionGroup` as children. Place `TopbarAction` buttons inside the group,
with `TopbarMenu` alongside it. Custom content can be composed directly into the
header. It follows the application theme unless `variant` is set to light or
dark. Use `<TopbarSidebarTrigger />` inside Layout or SidebarProvider; it
includes the navigation icon, accessible label, and sidebar toggle. It is hidden
on desktop. Topbar itself does not require a provider. The parts and
`TopbarMenu` are exported from the same topbar package.

`TopbarMenu` supports **Composition API only** and works outside Layout.
Use `TopbarMenuTrigger`, `TopbarMenuContent`, `TopbarMenuWorkspaceGroup`,
`TopbarMenuWorkspaceLabel`, `TopbarMenuWorkspaceItem`, and `TopbarMenuUser`.
The workspace group exposes shadcn radio-group `value`/`onValueChange`;
workspace items, user items, and ordinary shadcn items accept Base UI `render`
elements/functions for framework links. Use `TopbarMenuItem` (a direct shadcn alias) for
additional account actions.
The root supplies `currentWorkspace`/`user` context and loading/disabled state.
It does not generate actions or search UI. The examples show at most three recent
tenants including the current one; the application owns this data and updates
selection after switching succeeds. Compose language/theme submenus with the `TopbarMenuSub`,
`TopbarMenuSubTrigger`, `TopbarMenuSubContent`, `TopbarMenuRadioGroup`, and
`TopbarMenuRadioItem` aliases. TopbarMenu and Layout demonstrate working
preference changes; Layout also includes a profile page.
These components have no global function API.
